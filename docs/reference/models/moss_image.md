# MOSS-Image

MOSS-Image는 텍스트를 조건으로 이미지 latent의 velocity를 예측하는 단일 스트림 DiT다. 이 문서는 XAI 기법을 붙이기 전에 모델의 전체상과 볼 지점을 잡기 위한 개요다.

기호: B는 배치, h·w는 latent 그리드 크기, N = h·w는 이미지 토큰 수, L은 텍스트 토큰 수다.

## 전체 흐름

```
프롬프트 ─ 채팅 템플릿으로 감싸고 토큰화 ─────────────── 토큰 id [B,L]
  → 텍스트 인코더 Qwen3.5-9B, 마지막 층 ─────────────── [B,L,4096]
  → 텍스트 refiner: 사영 + 텍스트 전용 블록 2개 ───────── 텍스트 토큰 [B,L,3072]
노이즈 낀 latent x_t [B,128,h,w] → 펼쳐서 사영 ───────── 이미지 토큰 [B,N,3072]
  → [이미지 | 텍스트] 한 시퀀스 → DiT 블록 42개 ───────── [B,N+L,3072]
  → 이미지 토큰만 → 변조 norm → 사영 ─────────────────── velocity v [B,128,h,w]
타임스텝 σ → 임베딩 → 변조 벡터 6개 (모든 블록에 공급)
```

- 텍스트 인코더는 Qwen3.5-9B 언어 모델이고, 마지막 층 출력에 최종 norm을 적용한 값을 그대로 쓴다. 중간층은 쓰지 않는다.
- 텍스트 인코더는 단방향(causal)이다. 각 토큰은 자기보다 앞선 토큰만 본다. 그래서 프롬프트 앞에 붙는 템플릿 토큰은 프롬프트 내용을 전혀 담지 않는다.
- 텍스트 refiner는 인코더 출력(4096차원)을 DiT 폭(3072차원)으로 사영한 뒤, 텍스트 토큰끼리만 양방향 어텐션하는 블록 2개를 거친다. 이미지는 보지 않는다.
- DiT 출력은 velocity v다. 노이즈 보간이 x_t = σ·noise + (1−σ)·x0 이므로 깨끗한 이미지 예측은 x0 = x_t − σ·v 로 얻는다.
- latent는 Flux2 VAE가 만든다. VAE는 1/8 해상도의 32채널 latent를 만들고, 이를 2×2 칸씩 묶어 1/16 해상도의 128채널로 바꾼 뒤 고정 통계로 정규화한다. 그래서 이미지 토큰 1개는 원본 이미지의 16×16 픽셀에 해당한다.
- 규모: DiT는 블록 42개, 폭 3072, 헤드 24개(헤드당 128차원), FFN 폭 8192이며 약 5B 파라미터다. 텍스트 인코더와 VAE는 별도다.

## 블록 내부

```
x  ─┬────────────────────────────────────────────────────────────────── (+) → x'
    └ norm·변조1 → q,k,v → q·k norm → RoPE → 어텐션 → 출력 사영 → ×gate1 ┘
x' ─┬────────────────────────────────────────────────────────────────── (+) → x''
    └ norm·변조2 → FFN 확장 → 게이트 활성 → FFN 축소 → ×gate2 ───────────┘
```

- 블록은 pre-norm 구조다. 잔차 x에 먼저 어텐션 결과가, 그다음 MLP 결과가 더해진다. 두 갈래 모두 입력을 RMSNorm한 뒤 타임스텝으로 shift·scale 변조를 건다.
- 타임스텝 변조 벡터 6개(shift·scale·gate를 어텐션용과 MLP용으로 하나씩)는 블록마다 따로 있지 않다. 하나의 변조 출력을 42개 블록 전부가 공유하고, 이미지 토큰과 텍스트 토큰에 똑같이 적용된다.
- 그 함의: 같은 스텝 안에서 블록 간 차이는 오직 각 블록의 가중치에서 나온다. 타임스텝 조건을 바꿔 보는 개입은 모든 블록에 동시에 영향을 준다.
- 게이트는 (1+gate)가 아니라 gate 값 그대로 잔차에 곱해진다. 게이트는 채널별 값이고 타임스텝에만 의존하며 토큰 내용과는 무관하다. 따라서 어떤 채널의 gate가 0에 가까우면 그 스텝에서 그 채널로는 해당 갈래가 잔차에 거의 기여하지 못한다.
- MLP 활성은 FFN 확장 출력을 두 절반으로 나눠 한쪽을 게이트로 쓰는 게이트 활성이고, 양쪽 모두 값이 커지지 않도록 소프트캡이 걸려 있다.
- q와 k는 헤드별로 RMSNorm한 뒤 내적한다.
- 위치 임베딩은 4축 RoPE이며, q·k norm 다음에 q와 k에만 걸린다. v와 잔차 스트림에는 위치 정보가 직접 더해지지 않는다. 텍스트 refiner 블록에도 같은 방식으로 걸린다.
- 4개 축은 참조 이미지 번호, 시퀀스 위치, 행, 열이다. 텍스트 토큰은 시퀀스 위치 축에서 순서대로 번호를 받고, 행·열은 0이다. 생성 이미지 토큰은 시퀀스 위치 축에서 모두 텍스트 바로 뒤 한 자리를 공유하고, 행·열 축에 그리드 중앙 기준 좌표를 받는다. 참조 이미지는 참조 번호 축으로 구분된다.

|---|---|---|
| `te.out` | 텍스트 인코더 출력, 곧 refiner 입력 | [B,L,4096] |
| `refiner.proj` | refiner의 사영 출력 | [B,L,3072] |
| `refiner.block[j].resid_out` | refiner 블록 j의 출력 (j = 0, 1) | [B,L,3072] |
| `refiner.out` | DiT 시퀀스에 들어가는 텍스트 토큰 | [B,L,3072] |
| `img.embed` | 이미지 토큰 임베딩 | [B,N,3072] |
| `mod` | 타임스텝 변조 벡터 6개, 전 블록 공용 | 6×[B,1,3072] |
| `block[i].resid_in` / `resid_out` | 블록 i의 입력·출력 잔차 | [B,N+L,3072] |
| `block[i].attn.qkv_pre` | 사영 직후의 q, k, v (norm·RoPE 전) | 각각 [B,N+L,3072] |
| `block[i].attn.qk` | norm과 RoPE를 거친 q, k | [B,24,N+L,128] |
| `block[i].attn.v` | v | [B,24,N+L,128] |
| **`block[i].attn.probs`** | 어텐션 확률. 히트맵은 query [0,N) × key [N,N+L) 부분 | [B,24,N+L,N+L] |
| `block[i].attn.out` | 헤드를 합친 어텐션 출력, 출력 사영 전 | [B,N+L,3072] |
| `block[i].attn.proj` | 출력 사영 결과, gate1 곱하기 전 | [B,N+L,3072] |
| `block[i].mlp.act` | 게이트 활성 출력, FFN 축소 입력 | [B,N+L,8192] |
| `block[i].mlp.out` | FFN 축소 출력, gate2 곱하기 전 | [B,N+L,3072] |
| `final.out` | velocity | [B,128,h,w] |

## 토큰 시퀀스

- 이미지 그리드: DiT 안에서 추가 패치화가 없으므로 latent 한 칸이 토큰 하나다. 이미지 토큰은 행 우선 순서로 N = h·w개 놓인다.
- DiT의 시퀀스는 [이미지 N개 | 텍스트 L개] 하나다. 텍스트가 이미지 뒤에 놓이고, 둘은 마스크 없이 서로 전부 어텐션한다.
- 텍스트 토큰도 이미지 토큰과 같은 잔차 스트림에서 매 블록 갱신되고, 마지막 출력 단계에서만 버려진다. 그래서 뒤쪽 블록의 텍스트 토큰은 인코더가 준 프롬프트 표현 그대로가 아니라 이미지 정보가 섞인 표현이다. 텍스트 key를 해석할 때 이 점을 감안해야 한다.
- 내용 없는 토큰: 패딩은 없다. 텍스트 길이 L은 실제 토큰 수와 같다. 대신 프롬프트를 채팅 템플릿(사용자 턴 시작 표시, 사용자 턴 끝 표시, 어시스턴트 턴 시작과 열린 생각 블록)으로 감싸므로, 이 앞뒤 템플릿 토큰이 L에 포함되고 마스크 없이 모두 어텐션 key로 들어간다. 히트맵을 볼 때는 이 템플릿 토큰을 프롬프트 토큰과 구분해야 한다.
- 프롬프트 단어와 텍스트 위치의 대응: 템플릿을 포함한 전체 문자열을 byte-level BPE로 한 번에 토큰화하므로, 한 단어가 여러 토큰으로 쪼개질 수 있다. 인코더, refiner, DiT 모두 토큰의 순서와 개수를 보존하므로 인코더의 텍스트 토큰 j는 DiT 시퀀스의 위치 N+j다. 단어 위치는 토큰 id를 하나씩 디코드해 프롬프트 문자열과 맞춰서 구한다.
- 편집용 참조 이미지가 있으면 그 토큰이 시퀀스 끝(또는 key·value 끝)에 추가로 붙을 수 있다.

# Krea 2

Krea 2는 텍스트→이미지 flow 모델이다. 텍스트 토큰과 이미지 토큰을 한 시퀀스로 이어 붙여 같은 블록에 통과시키는 single-stream DiT다. 아래 shape 표기에서 B는 배치, T는 DiT에 들어가는 텍스트 토큰 수, N은 이미지 토큰 수, F는 DiT 폭(6144)이다.

## 전체 흐름

```
프롬프트 ──(chat 템플릿에 끼움)──→ 토크나이저
  → Qwen3-VL-4B 언어 모델 (36층, 폭 2560, 단방향)
  → 12개 층의 hidden을 그대로 쌓음, system 접두부는 잘라냄      [B, T, 12, 2560]
┌ DiT ───────────────────────────────────────────────────────────────┐
│ 텍스트: txtfusion (12층 혼합 → 토큰 간 정제) → MLP     → [B, T, F]  │
│ 이미지: latent를 2×2 패치로 묶어 선형 사상             → [B, N, F]  │
│ 시간:   σ → 임베딩 → MLP → 블록 변조용 벡터 tvec                    │
│ [텍스트 | 이미지] → 블록 28개 → 마지막 변조·선형 층                 │
│ 이미지 구간만 다시 latent 모양으로                     → velocity v │
└────────────────────────────────────────────────────────────────────┘
  → x0 = x_σ − σ·v → VAE 디코드 → 이미지
```

- 텍스트 인코더는 Qwen3-VL-4B의 언어 모델 부분이다. 텍스트 프롬프트만 쓸 때 비전 타워는 쓰이지 않는다.
- 이 언어 모델은 causal 마스크로 도는 단방향 LLM이다. 그래서 각 토큰의 상태는 자기 앞의 토큰(템플릿 접두부 포함)만 본 결과이고, 프롬프트 뒤쪽 토큰일수록 앞 내용을 더 많이 담는다.
- 최종 층 하나가 아니라 36층 가운데 3층 간격의 12개 층에서 hidden을 뽑는다. 각 hidden은 그 층에 들어가는 잔차 스트림이며 final norm은 붙지 않는다.
- 12개 층을 어떻게 섞을지는 텍스트 인코더 쪽이 아니라 DiT 안의 txtfusion이 학습으로 정한다. txtfusion은 먼저 토큰마다 12개 층 축 위에서 어텐션을 하고, 12층을 1층으로 선형 혼합한 뒤, 토큰 축 위에서 양방향 어텐션으로 정제한다.
- DiT의 출력은 flow velocity v다. 노이즈 낀 latent는 x_σ = σ·ε + (1−σ)·x0 이고, 깨끗한 latent 예측은 x0 = x_σ − σ·v 로 얻는다. 즉 v는 대략 ε − x0 를 가리킨다.
- 타임스텝 입력은 σ ∈ [0, 1] 이다.
- 규모는 블록 28개, 폭 6144, DiT 약 12.8B 파라미터다.
- latent는 16채널이고 VAE가 공간을 8배 줄인다(Qwen-Image VAE).

## 블록 하나의 내부

```
x ─ RMSNorm, (1+s1)·· + b1 ─→ h
      h → q (48헤드), k·v (12헤드) → QK-norm → RoPE → softmax(q·kᵀ/√128)·v ─┐
      h → sigmoid(Wg·h) ── 출력 게이트 ──────────────────────────────────── ⊙ ─→ Wo
x ← x + g1 ⊙ (어텐션 출력)
x ─ RMSNorm, (1+s2)·· + b2 → SwiGLU MLP
x ← x + g2 ⊙ (MLP 출력)
```

- pre-norm 잔차 구조다. 잔차에는 어텐션 출력이 먼저, MLP 출력이 다음으로 더해진다.
- 타임스텝 조건은 AdaLN 방식으로 들어간다. 모든 블록이 같은 tvec 하나를 공유하고, 블록마다 학습된 bias만 더해 shift·scale·gate 6개 벡터(s1, b1, g1, s2, b2, g2)를 만든다.
- 이 6개 벡터는 모든 토큰에 똑같이 적용되고 채널마다만 다르다.
- 블록은 28개, 폭은 6144, head 차원은 128이다.
- 어텐션에는 마스크가 없어 모든 토큰이 모든 토큰을 양방향으로 본다.

어텐션 확률만으로는 기여가 정해지지 않는다. 확률 외에 기여를 바꾸는 요소가 셋 있다.

- 출력 게이트 sigmoid(Wg·h)는 토큰마다, 채널마다 다른 값이다. 헤드를 이어 붙인 어텐션 값에 Wo 전에 곱해지므로, 확률이 높아도 게이트가 닫히면 그 결과는 잔차에 거의 닿지 않는다.
- 타임스텝 게이트 g1, g2는 채널마다 다른 값이고 잔차에 더하기 직전에 곱해진다. σ에 따라 값이 달라지므로 같은 블록이라도 스텝마다 어텐션·MLP의 영향력이 다르다.
- q헤드는 48개, k/v헤드는 12개(GQA)다. q헤드 4개가 k/v헤드 하나를 공유하므로, 같은 그룹의 헤드들은 같은 key·value 위에서 서로 다른 확률 분포만 만든다.

위치 임베딩은 3축 RoPE(참조 이미지 번호, 행, 열)이고, 모든 DiT 블록에서 QK-norm 뒤의 q·k에 걸린다. 이미지 토큰은 자기 행·열 좌표를 받지만, 텍스트 토큰은 전부 (0, 0, 0)이라 회전되지 않는다. 따라서 DiT 안에서 텍스트 토큰에는 위치 정보가 없고, 단어 순서는 텍스트 인코더가 만든 상태 안에만 들어 있다. txtfusion에도 위치 임베딩이 없다.

## 개입 지점

shape는 구현과 무관한 논리적 모양이다.

| 지점 | 의미 | shape |
|---|---|---|
| `te.hidden[k]` | 텍스트 인코더 k층의 입력 잔차 (12개 중 하나) | [B, S, 2560], S는 접두부 포함 토큰 수 |
| `text_in` | DiT에 들어오는 12층 스택 (접두부 제거 후) | [B, T, 12, 2560] |
| `txtfusion.layerwise_out` | 층 축 어텐션을 거친 12층 스택 | [B, T, 12, 2560] |
| `txtfusion.proj_out` | 12층을 1층으로 선형 혼합한 결과 | [B, T, 2560] |
| `txtfusion.out` | 토큰 간 정제를 마친 텍스트 | [B, T, 2560] |
| `txt_embed` | DiT 텍스트 토큰의 초기값 | [B, T, F] |
| `img_embed` | 패치 임베딩, DiT 이미지 토큰의 초기값 | [B, N, F] |
| `temb` | 타임스텝 임베딩과 변조 벡터 tvec | [B, 1, F] / [B, 1, 6F] |
| `block[i].resid_in` / `resid_out` | 블록의 입력·출력 잔차 | [B, T+N, F] |
| `block[i].attn.qkv_pre` | QK-norm 뒤, RoPE 앞의 q / k·v | [B, 48, T+N, 128] / [B, 12, T+N, 128] |
| `block[i].attn.qkv` | RoPE와 k·v 반복 뒤의 q·k·v | [B, 48, T+N, 128] |
| **`block[i].attn.probs`** | 어텐션 확률; 히트맵은 이미지 query × 텍스트 key 구간 | [B, 48, T+N, T+N] |
| `block[i].attn.ctx` | 헤드를 이어 붙인 어텐션 값, 게이트 전 | [B, T+N, 6144] |
| `block[i].attn.gate` | 출력 게이트 sigmoid(Wg·h) | [B, T+N, 6144] |
| `block[i].attn_out` | Wo 뒤, g1을 곱하기 전 어텐션 기여 | [B, T+N, F] |
| `block[i].mlp_out` | g2를 곱하기 전 MLP 기여 | [B, T+N, F] |
| `final` / `v` | 토큰별 출력 패치 / 이미지 구간을 되돌린 velocity | [B, T+N, 64] / [B, 16, 1, h, w] |
| `x0` | 깨끗한 latent 예측 x_σ − σ·v | [B, 16, 1, h, w] |

## 토큰 시퀀스

- 이미지 토큰: latent(16 × h × w)를 2×2 패치로 묶은 그리드다. 높이·너비가 홀수면 짝수로 패딩한 뒤 묶고, 출력 때 패딩을 잘라낸다. 그리드는 행 우선으로 펼친다(토큰 번호 = 행 × 그리드 너비 + 열).
- 한 시퀀스는 [텍스트 T개 | 이미지 N개] 순서다. 텍스트 구간이 앞이므로 이미지 토큰은 T번 위치부터 시작한다.
- 텍스트 토큰도 블록마다 이미지 토큰과 같은 가중치, 같은 변조로 갱신된다. 그래서 깊은 블록의 텍스트 key는 이미 이미지 정보를 섞은 상태다.
- 마지막 출력에서 텍스트 구간은 버려진다. 따라서 텍스트가 이미지에 기여하는 길은 각 블록에서 이미지 query가 텍스트 key·value에 어텐션하는 것뿐이다.
- 텍스트 T개는 프롬프트 토큰 뒤에 템플릿 꼬리 5토큰(`<|im_end|>`, 줄바꿈, `<|im_start|>`, `assistant`, 줄바꿈)이 붙은 것이다.
- 꼬리 토큰은 그 자체로 내용이 없지만, 인코더가 단방향이라 프롬프트 전체를 본 상태를 담는다. 마스크도 없으므로 이 상태가 그대로 DiT 어텐션의 key로 들어간다.
- 패딩 토큰은 없다. 토크나이저가 최대 길이로 채우지 않고, 인코더의 attention mask도 DiT로 넘어가지 않는다.
- system 턴과 user 턴 시작 부분(접두부)은 텍스트 인코더 안에서 문맥으로만 쓰이고, DiT 입력에서는 잘린다.
- 프롬프트 단어 ↔ 텍스트 위치: 템플릿 전체 문자열이 한 덩어리로 토크나이즈되므로 단어 경계 정보가 따로 없다. DiT 텍스트 위치 j는 인코더 토큰 번호 (접두부 길이 + j)와 같다. 같은 토크나이저로 템플릿을 토크나이즈하고, 접두부를 빼고, 각 토큰을 문자열로 되돌려 단어에 맞춘다.
- 토크나이저는 byte-level BPE다. 한 단어가 여러 토큰으로 쪼개질 수 있고, 단어 앞의 공백은 그 단어의 첫 토큰에 붙는다.
